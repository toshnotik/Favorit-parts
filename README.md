# Favorit Parts

Тестовое приложение для поиска автозапчастей: артикул → производитель → предложения и аналоги. Адаптивный интерфейс, индикаторы загрузки, ошибки и пустые результаты. Повторный поиск очищает предыдущий результат; устаревшие ответы не перезаписывают новый поиск.

## Стек и запуск

React, JavaScript (без TypeScript), Vite, Redux Toolkit, Bootstrap 5, CSS. Требуется Node.js 22.12+ и npm.

```sh
npm ci
npm run dev
```

Откройте адрес, который выведет Vite (обычно http://localhost:5173).

```sh
npm test
npm run build
npm run preview
```

## Демонстрационный режим

Работает по умолчанию, без ключа, сервера и запросов к Favorit. Приложение явно показывает отметку DEMO. Задержка ответа 550 мс позволяет проверить загрузку.

- `7160500039S` — два производителя, аналоги, предложения разных складов и позиция без остатка.
- `7260500039S` или любой неизвестный артикул — пустой результат.
- `ERROR` — демонстрация ошибки `Request quota exceeded!`.

Данные вымышлены, структура основана на **«Документация по API.pdf»**, включая изображения JSON на страницах 4–5. Исходный PDF хранится локально и исключён из Git. Контракт описан ниже, поэтому файл не нужен для запуска. Это демонстрационный каталог, а не актуальные цены или сведения о совместимости.

На компьютере предложения отображаются таблицей, на экранах до 767 px — компактными карточками на основе той же семантической таблицы. Все поля остаются доступны без горизонтальной прокрутки. Есть видимый фокус клавиатуры, подписи полей, озвучивание загрузки и ошибок, поддержка уменьшения движения.

## Контракт API

Документ от 06.03.2023 описывает GET `http://api.favorit-parts.ru/hs/hsprice/`:

- `key` — ключ покупателя, `number` — артикул;
- без `brand` возвращаются товары разных производителей;
- с `brand` и `analogues=on` возвращаются аналоги в `goods[].analogues`;
- `info=on` опционально включает `notRefund`, в этом задании не требуется.

Ответ — `{ goods: [...] }`. Товар содержит `goodsID`, `brand`, `number`, `name`, `count`, `price`, `rate`, `warehouses` и, при запросе аналогов, `analogues`. Склад содержит `id`, необязательный `code`, `own`, `shipmentDate`, `price`, `stock`. Каждое складское предложение выводится отдельной строкой. Используются **только `warehouses[].price` и `warehouses[].stock`**. Поле `goods[].price` устарело и не используется. Для товара без складов цена отображается как «—», остаток — «Нет в наличии».

Документированный ответ при отсутствии товара — `goods` с одной пустой структурой, а не обязательно пустой массив; API-модуль отфильтровывает её. Ошибка — `{ error: "..." }`.

## Подключение реального API

**Потребуется настоящий ключ доступа покупателя от Favorit Parts.** Ключ в PDF приведён как пример и в приложение не встроен. Реальные запросы без ключа не выполнялись.

1. Скопируйте `.env.example` в `.env`.
2. Установите `VITE_API_MODE=real`, заполните `FAVORIT_API_KEY` своим ключом.
3. В одном терминале запустите `npm run server`, в другом — `npm run dev`.

Минимальный серверный прокси на Node.js слушает только `127.0.0.1:3001`. `/api/price` — **внутренний маршрут приложения**, не выдуманный endpoint Favorit. Vite направляет его к серверу. Прокси добавляет ключ на сервере и кодирует параметры через `URLSearchParams`; клиент ключ не получает. Не используйте префикс `VITE_` для секретов. `.env` исключён из Git.

В PDF указан HTTP, поэтому сервер использует именно этот адрес. Перед эксплуатацией уточните у поставщика защищённый адрес HTTPS: документированный HTTP передаёт ключ без транспортного шифрования. Ключ и URL с ним не логируются. Прокси предназначен для локальной проверки; для публикации потребуется сервер с ограничением доступа и маршрутизацией `/api/price` к нему. GitHub Pages может размещать только демонстрационную статическую сборку, серверный прокси там не работает. В режиме real перезапустите Vite после изменения `.env`.

## Структура

```text
src/App.jsx          — интерфейс
src/styles.css       — адаптивные стили поверх Bootstrap
src/store/search.js  — Redux, async thunks, защита от устаревших ответов
src/api/parts.js     — переключение транспорта и подготовка предложений
src/api/mock.js      — демонстрационные ответы по контракту PDF
src/App.test.jsx     — сценарии поиска и проверка складских цен
server/index.js      — опциональный серверный прокси
```

## GitHub Pages

Подготовлен workflow `.github/workflows/pages.yml`: установка через `npm ci`, проверка форматирования, тесты, сборка и публикация только каталога `dist`. В сборке явно устанавливается `VITE_API_MODE=demo`; API-ключ не требуется. Настройка основана на [официальной инструкции Vite](https://vite.dev/guide/static-deploy.html#github-pages).

После проверки проекта и самостоятельной публикации исходников:

1. В репозитории GitHub откройте **Settings → Pages → Source → GitHub Actions**.
2. Workflow автоматически запускается при push в `main`. Если основная ветка называется иначе, измените `on.push.branches` в workflow.
3. Также его можно запустить вручную: **Actions → Deploy demo to GitHub Pages → Run workflow** (после добавления workflow в основную ветку).
4. Адрес опубликованного сайта появится в результате задания `deploy`.

В Vite установлен относительный `base: "./"`: пути к ресурсам работают и в корне домена, и под `/favorit-parts/`, и при переименовании репозитория. В приложении нет клиентских маршрутов, поэтому отдельный fallback для SPA не требуется. Сайт публикуется существующим workflow из ветки `main`.

Проверка production-сборки локально: `npm run build`, затем `npm run preview`. Статическая версия полностью работает без прокси и внешних шрифтов.
